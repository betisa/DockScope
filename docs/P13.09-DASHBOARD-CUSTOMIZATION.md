# P13.09 — Dashboard Customization

> Milestone: M13 — Advanced Diagnostics & Operations  
> Status: Implemented

## Objective

Turn the Dashboard from a fixed overview into a persistent, user-configurable operational workspace without moving privileged settings or Docker execution into Renderer state.

## Customizable Widgets

The dashboard now supports these widgets:

- Runtime Summary
- Storage Chart
- Container States
- Storage Details
- Unhealthy Containers
- Recent Builds
- Top Volumes
- Recent Alerts
- Quick Actions

Runtime Summary is treated as an essential widget and cannot be hidden.

## Layout Preference

Dashboard customization is a UI preference persisted through Main-process Knex/SQLite under:

```text
app_state key:
ui.dashboard.layout.v1
```

Schema:

```text
schemaVersion
density
order[]
hidden[]
```

The preference contains no Docker secrets or privileged configuration.

## Safe Normalization

Saved layouts are normalized before use.

Normalization:

- removes unknown widget IDs;
- removes duplicate IDs;
- appends new product widgets missing from an older saved layout;
- prevents Runtime Summary from being hidden;
- defaults unknown density to Comfortable;
- falls back to the default layout when JSON is invalid.

This provides forward compatibility when new dashboard widgets are added.

## Visibility

Optional widgets can be shown or hidden independently.

Hiding a widget affects presentation only.

It does not:

- stop monitoring;
- stop Storage Trends;
- change Docker resources;
- delete data;
- change Task Center behavior.

## Reordering

Two reorder methods are available.

### Drag and Drop

Visible dashboard widgets can be dragged directly to a new position.

### Keyboard-Accessible Reorder

The Customize panel provides:

```text
Move Up
Move Down
```

for every widget.

This avoids making drag-and-drop the only reordering mechanism.

## Density

Two density modes are available:

```text
Comfortable
Compact
```

Compact mode reduces:

- gaps;
- metric card height;
- chart/card spacing;
- storage cards;
- quick-action padding.

It does not remove information.

## Customize Dialog Accessibility

The Customize panel:

- uses `role="dialog"`;
- uses `aria-modal="true"`;
- moves focus into the panel;
- traps Tab / Shift+Tab;
- closes with Escape;
- restores previous focus on close;
- supports backdrop close;
- exposes descriptive labels for reorder controls.

## New Operational Widgets

### Unhealthy Containers

Uses the current container inventory.

Rows link to:

```text
Container
  ↓
Advisor
```

### Recent Builds

Uses current Buildx history.

Shows:

- name / Build ID fallback;
- creation time;
- duration;
- status.

### Top Volumes

Uses Volume Intelligence.

Rows are sorted by Docker-reported size and show:

- volume name;
- current references;
- detected workload;
- size;
- risk level.

### Recent Alerts

Uses Operational Intelligence notifications.

Shows the latest Warning and Critical entries.

### Existing Widgets

The existing Storage Chart, Container State Chart, Storage Details and Quick Actions are now independent reorderable widgets.

## Data Loading

Dashboard core data remains strict:

- Engine Status
- Disk Usage
- Container Inventory

Optional intelligence widgets fail independently:

- Buildx History
- Volume Intelligence
- Notifications

If one optional collector is unavailable, the whole Dashboard does not fail.

## Persistence Boundary

Dashboard customization uses the generic typed `preferences` IPC boundary. Renderer never opens SQLite or submits SQL; Main persists the normalized layout in `app_state`.

## Reset

**Reset Default Layout** removes the saved key and restores:

- default order;
- all optional widgets visible;
- Comfortable density.

## Compact navigation actions

Dashboard widget destination links use compact icon buttons with tooltips and accessible `aria-label` text rather than long inline link labels.

The Container Diagnostics widget surfaces current problem states from Docker list metadata:

- unhealthy;
- dead;
- restarting;
- non-zero exited.

Selecting a problem container writes an explicit one-time deep-link to **Containers → Advisor**. The Containers page resolves by container ID with a name fallback and consumes the intent once.
