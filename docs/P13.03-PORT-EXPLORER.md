# P13.03 — Port Explorer

> Milestone: M13 — Advanced Diagnostics & Operations  
> Status: Implemented

## Objective

Provide one global, searchable Docker port inventory that connects host bindings to containers and Docker Compose ownership while making exposure and binding conflicts obvious.

## Data Sources

Port Explorer intentionally uses Docker inspection data as the authoritative source:

```text
docker container ls -a --no-trunc --format json
        ↓
docker container inspect <all container ids>
        ↓
.NetworkSettings.Ports
.Config.Labels
.State.Status
```

`NetworkSettings.Ports` supplies container-port / protocol mappings and HostIp / HostPort bindings.

Compose ownership is inferred from standard Docker Compose labels:

```text
com.docker.compose.project
com.docker.compose.service
```

## Port Binding Model

Each row contains:

- Container ID
- Container name
- Container state
- Image
- Compose project
- Compose service
- Host IP
- Host port
- Container port
- Protocol
- Published/routed status
- Exposure classification
- Endpoint
- Suggested HTTP(S) URL when appropriate
- Conflict status and conflicting containers

## Exposure Classification

```text
0.0.0.0 / empty + HostPort → all-interfaces
:: + HostPort              → ipv6-all
127.0.0.1 / ::1            → loopback
specific address           → specific-interface
no HostPort                → routed
```

The page highlights all-interface bindings because their reachability may extend beyond localhost depending on host firewall and network configuration.

## Conflict Detection

Conflict detection is:

- Host-port aware
- Protocol aware
- IP-family aware
- Wildcard aware
- Limited to active/running container bindings

Rules:

```text
same TCP host port + same host IP       → conflict
same UDP host port + same host IP       → conflict
TCP 8080 vs UDP 8080                    → not a conflict
0.0.0.0:8080/tcp vs 127.0.0.1:8080/tcp → conflict
:::8080/tcp vs ::1:8080/tcp             → conflict
inactive/stopped binding                → visible, no live conflict alert
```

## Browser Endpoint Heuristic

The app offers **Open** only when:

1. protocol is TCP;
2. the host port is published;
3. host/container port resembles a common HTTP(S) development port.

HTTPS is preferred for known HTTPS-style ports such as 443, 8443, and 9443.

The actual browser launch happens in Electron Main. Renderer cannot call `shell.openExternal` directly.

Main validates:

- protocol must be HTTP or HTTPS;
- host must be `localhost` or a literal IPv4/IPv6 address;
- URL length is bounded.

## UI

Port Explorer is a first-class **Resources** page.

Features:

- Summary metrics
- Search
- 10-row pagination
- Protocol filter
- Container-state filter
- Exposure filter
- Conflicts-only Switch
- Compose ownership
- Copy endpoint / URL
- Open likely HTTP(S) endpoint
- Deep-link to Container → Ports tab
- Deep-link to Compose project
- Conflict-model explanation
- Contextual Guide

## Safety

Port Explorer itself is read-only.

It does not:

- publish ports;
- unpublish ports;
- mutate container networking;
- modify Compose YAML;
- stop conflicting containers automatically.

Conflict resolution remains an explicit user action in the owning Container or Compose project.
