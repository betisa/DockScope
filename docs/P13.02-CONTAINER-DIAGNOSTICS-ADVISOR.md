# P13.02 — Container Diagnostics Advisor

## Objective

Add a read-only, evidence-driven diagnostics advisor to every Container Workspace. The advisor correlates Docker inspect state, health-check metadata, recent logs, and a single non-streaming stats snapshot to surface known failure patterns without inventing unsupported root causes.

## Data sources

```text
Container
   ├── docker container inspect
   │     ├── State / ExitCode
   │     ├── OOMKilled
   │     ├── RestartCount
   │     ├── State.Error
   │     └── Health
   ├── docker container logs --timestamps --tail 400
   └── docker stats --no-stream --format json
         ├── CPU
         ├── Memory
         ├── Network I/O
         ├── Block I/O
         └── PIDs
```

## Advisor output

Each finding uses the same structure:

```text
Symptom
   ↓
Evidence
   ↓
Likely Cause
   ↓
Recommended Actions
```

The advisor does not execute repair actions. Log evidence is also passed through basic secret-pattern redaction before being returned to the Renderer.

## Implemented diagnostic rules

### OOMKilled

High-confidence Critical finding when Docker inspect reports:

```text
State.OOMKilled = true
```

Evidence also includes the container exit code.

### Exit code 137 without OOMKilled

Reported as a warning rather than definite OOM. Exit 137 indicates SIGKILL, but memory pressure is only one possible cause.

### Non-zero process exit

For stopped containers with a non-zero exit code, the advisor reports process termination evidence and directs the user to logs, command/entrypoint, and configuration.

### Restart loop indicator

Triggered when `RestartCount >= 3`.

- 3–9 restarts → Warning
- 10+ restarts → Critical

This is a heuristic signal, not proof of a restart loop.

### Unhealthy container

Triggered by Docker health state `unhealthy`, using:

- failing streak;
- configured health command;
- recent health-check exit/output evidence.

### Log-pattern findings

Evidence is included only when a matching recent log line exists:

- port/address already in use;
- permission denied / EACCES;
- no space left on device / ENOSPC;
- DNS/name-resolution failures;
- connection refused / ECONNREFUSED;
- missing required environment/configuration patterns.

### Runtime resource pressure

From a point-in-time Docker Stats snapshot:

- Memory >= 90% → Warning
- Memory >= 97% → Critical
- CPU >= 95% → Warning

The UI explicitly recommends using Live Stats to verify whether CPU pressure is sustained.

## UI

Container Workspace now opens on the **Advisor** tab by default.

Tabs:

```text
Advisor
Overview
Logs
Stats
Processes
Health
Ports
Mounts
Networks
Environment
Inspect
Terminal
```

Advisor contains:

- overall status summary;
- Critical/Warning counts;
- sampled log-line count;
- State / Exit Code / OOM / Restarts / Health / Memory / CPU / PIDs facts;
- structured finding cards;
- Analyze Again action;
- explicit scope disclaimer.

## Security

No new privileged capability is exposed directly to the Renderer.

```text
Renderer
  ↓ containers.advisor(id)
Preload typed API
  ↓
validated IPC
  ↓
Electron Main
  ↓
Docker CLI
```

Container IDs continue through the existing `safeIds()` IPC validation.

## Acceptance criteria

- [x] Advisor available from every Container Workspace.
- [x] OOMKilled, exit, restart, health, log-pattern, memory, and CPU rules implemented.
- [x] No finding is generated for log patterns without matching log evidence.
- [x] Exit 137 without `OOMKilled=true` is not labeled as confirmed OOM.
- [x] Advisor is read-only.
- [x] Overview displays Exit Code, Restarts, and OOMKilled.
- [x] Healthy/no-match state is explicitly represented.
- [x] Mock Docker scenarios cover critical and healthy advisor outcomes.
- [x] TypeScript/TSX syntax validation passes.
