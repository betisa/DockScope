# P13.04 — Volume Intelligence

> Milestone: M13 — Advanced Diagnostics & Operations  
> Status: Implemented

## Objective

Transform the Volumes page from a basic Docker inventory into a persistent-data intelligence workspace that answers:

- Which containers mount this volume?
- Which Compose project/service owns it?
- Where is it mounted inside the container?
- Is it read/write or read-only?
- What type of workload likely stores data here?
- How large is it?
- What Docker labels/options describe it?
- How risky would deletion be?
- What backup/export should be considered first?

## Authoritative Docker Data

Volume Intelligence combines:

```text
docker volume ls --format json
docker volume inspect <volume...>
docker system df -v
docker container ls -a --no-trunc --format json
docker container inspect <container...>
```

`docker volume inspect` supplies:

- CreatedAt
- Driver
- Scope
- Mountpoint
- Labels
- Options

`docker system df -v` supplies per-volume Docker disk usage.

Container `Mounts` supplies:

- volume name
- container destination
- read/write state

Container labels supply Compose ownership:

```text
com.docker.compose.project
com.docker.compose.service
```

## Workload Detection

P13.04 detects common persistent workloads from Docker metadata only.

Current signatures:

- PostgreSQL
- MySQL / MariaDB
- SQL Server
- MongoDB
- Redis
- MinIO
- Elasticsearch
- Generic application data

Evidence may include:

- container image;
- mount destination;
- volume name;
- container/service/project name;
- volume labels.

Confidence:

```text
High   known image and/or canonical data mount path
Medium workload identifier from metadata/name/labels
Low    generic application-data relationship only
```

No filesystem content scanning is performed.

## Risk Score

Risk is deliberately conservative.

Signals include:

- current container references;
- detected persistent database/storage workload;
- Compose ownership;
- volume labels;
- volume size.

Output:

```text
Medium
High
Critical
```

Deletion assessment is intentionally **not** `safe`.

Possible values:

```text
Blocked
High Risk
Review Required
```

### Blocked

Used when one or more current container references exist.

### High Risk

No current reference, but persistent workload, Compose ownership, or explicit labels indicate meaningful application ownership.

### Review Required

No current references and no strong ownership/workload signal. This still does not prove that the data is disposable.

## Latest Related Container Timestamp

`latestRelatedContainerAt` represents the newest creation timestamp among containers that currently reference the volume.

It is **not** a last-read / last-write timestamp and must not be interpreted as proof of last data access.

Docker does not expose a generic volume last-access time through the standard volume metadata used by this feature.

## Backup Guidance

Workload-specific hints are shown before deletion.

Examples:

- PostgreSQL → pg_dump / pg_dumpall or verified storage snapshot
- MySQL / MariaDB → mysqldump / mariadb-dump
- SQL Server → verified database backup
- MongoDB → mongodump
- Redis → verify RDB/AOF persistence requirements
- MinIO → verify object replication/export
- Elasticsearch → snapshot repository

These are guidance only; P13.04 does not execute backup commands automatically.

## Deletion Safety

Removal is not shown when a current container reference exists.

For unreferenced volumes, removal still requires typed confirmation:

```text
DELETE <volume-name>
```

The confirmation includes risk score and deletion assessment.
