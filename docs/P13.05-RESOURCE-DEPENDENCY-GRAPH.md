# P13.05 — Resource Dependency Graph

> Milestone: M13 — Advanced Diagnostics & Operations  
> Status: Implemented

## Objective

Provide a global, read-only Docker topology that makes ownership and blast radius visible before troubleshooting or destructive changes.

The graph answers:

- Which Compose project owns this service/container?
- Which image does a container use?
- Which persistent volumes does it mount?
- Which Docker networks is it attached to?
- Which host ports does it publish?
- Which images, volumes, networks, or ports are shared by multiple containers?
- What resources are directly upstream/downstream from a selected resource?

## Relationship Model

```text
Compose Project
      ↓ contains
Compose Service
      ↓ runs
Container
  ├── uses-image ─────→ Image
  ├── mounts ─────────→ Volume
  ├── connected-to ───→ Network
  └── publishes ──────→ Host Port
```

Standalone containers are represented without artificial Compose ownership.

## Authoritative Data

The graph is built from:

```text
docker container ls -a --no-trunc --format json
docker container inspect <all container ids>
```

Container inspect contributes:

- `Config.Image`
- image ID
- `Config.Labels`
- `State`
- `Mounts`
- `NetworkSettings.Networks`
- `NetworkSettings.Ports`

Compose ownership uses:

```text
com.docker.compose.project
com.docker.compose.service
```

No filesystem scan or application traffic inspection is performed.

## Node Types

- Compose Project
- Compose Service
- Container
- Image
- Volume
- Network
- Published Port

Node IDs are stable within the current Docker snapshot:

```text
compose-project:<project>
compose-service:<project>:<service>
container:<container-id>
image:<image-id-or-name>
volume:<volume-name>
network:<network-id-or-name>
port:<host-ip>:<host-port>:<protocol>
```

## Shared Resources

Images, volumes, networks, and published-port nodes are deduplicated.

A resource is marked **shared** when it has more than one incoming relationship.

Examples:

```text
container-a ─┐
             ├──→ network: backend
container-b ─┘
```

```text
container-a ─┐
             ├──→ image: sha256:...
container-b ─┘
```

This helps estimate blast radius before cleanup, image replacement, network changes, or volume operations.

The Resource Graph page provides:

- summary counts for every node category;
- shared-resource count;
- deterministic multi-column layout;
- scrollable SVG topology;
- search;
- resource-type filtering;
- selected-neighborhood focus;
- optional edge labels;
- keyboard-selectable graph nodes;
- incoming/outgoing dependency panel;
- metadata/evidence panel;
- resource deep links;
- in-page contextual Guide.

## Search

Search covers:

- labels;
- subtitles;
- resource type;
- resource IDs;
- Compose project/service;
- graph metadata such as image, IP, gateway, mount destination, protocol, host port.

Search preserves immediate neighboring nodes so matching resources remain understandable in context.

## Resource Filter

Selecting a resource type keeps matching nodes plus directly connected context nodes.

Examples:

```text
Volumes
→ matching volume nodes
→ containers mounting those volumes
```

```text
Compose Services
→ services
→ directly connected projects and containers
```

## Focus Selected Neighborhood

When enabled, only the selected node and its immediate incoming/outgoing relationships remain visible.

This is useful in large topologies.

## Resource Details

Selecting a node opens:

- incoming dependencies;
- outgoing dependencies;
- resource metadata;
- Compose ownership where applicable;
- state where applicable;
- Open Resource action.

- `role="button"`

## Performance

P13.05 deliberately does not add React Flow, Cytoscape, D3, or another heavyweight graph dependency.

Layout is deterministic and calculated from node type/order.

Benefits:

- no graph-engine bundle increase;
- no WebGL/canvas dependency;
- predictable output;
- straightforward accessibility;
- stable topology between refreshes when resource names remain stable.

## Limitations

The graph is a **current Docker metadata snapshot**.

It does not prove:

- application traffic between containers;
- database reads/writes;
- last volume access;
- network packet flow;
- runtime service calls.

A network relationship means container attachment, not communication with every peer on that network.

## Safety

Resource Graph is read-only.

It performs no:

- container mutation;
- volume removal;
- network removal;
- image removal;
- port modification;
- Compose file modification.

Destructive actions remain in the owning resource pages with their existing safeguards.
