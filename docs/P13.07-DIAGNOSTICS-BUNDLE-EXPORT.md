# P13.07 — Diagnostics Bundle Export

> Milestone: M13 — Advanced Diagnostics & Operations  
> Status: Implemented

## Objective

Generate one shareable troubleshooting ZIP from the application's current Docker/Windows diagnostic state while applying mandatory best-effort redaction before any collected content is written into the archive.

The feature is available from:

```text
Overview
  ↓
Audit & Recovery
  ↓
Export diagnostics bundle
```

## Bundle Structure

A typical bundle contains:

```text
DockScope-Diagnostics-<timestamp>.zip
├── README.txt
├── manifest.json
├── system/
│   ├── app.json
│   ├── settings.json
│   ├── docker-version.txt
│   ├── docker-info.txt
│   └── docker-context.txt
├── docker/
│   ├── engine-status.json
│   ├── disk-usage.json
│   ├── containers.json
│   ├── compose-projects.json
│   ├── images.json
│   ├── networks.json
│   ├── ports.json
│   ├── resource-graph.json
│   ├── volumes.json
│   ├── builders.json
│   ├── build-history.json
│   └── build-cache.json
├── containers/
│   └── <container>-<short-id>/
│       ├── diagnostics.json
│       └── logs.txt
├── storage/
│   └── vhdx.json
├── monitoring/
│   ├── health.json
│   └── notifications.json
└── operations/
    ├── tasks.json
    ├── task-summary.json
    ├── audit-summary.json
    ├── audit-history.json
    └── recovery-snapshots.json
```

## Independent Collectors

Every data source is treated as an independent collector.

Collector states:

```text
success
failed
skipped
```

A failed collector does not abort the complete bundle.

`manifest.json` records:

- collector name;
- output file;
- collector state;
- sanitized error message;
- generated file size;
- global warnings;
- collection limits.

This is important when Docker Desktop is partially unavailable.

## Container Limits

Per-container collection is bounded:

```text
Maximum containers: 25
Recent log tail:    300 lines
```

If more containers exist, the global container inventory is still included but only the first 25 receive individual diagnostics and log files.

The limit is written into `manifest.json`.

## Redaction Pipeline

Redaction is mandatory and independent from the user's normal UI secret-masking setting.

Before bundle content is written, the exporter applies:

1. recursive sensitive-key masking;
2. `KEY=value` environment-variable masking;
3. password/token/API-key/client-secret/access-key/private-key patterns;
4. Authorization Bearer masking;
5. connection-string masking;
6. password-bearing URL masking;
7. current home-directory replacement with `%USERPROFILE%`.

Example:

```text
PASSWORD=hello
→
PASSWORD=***
```

```text
Authorization: Bearer eyJ...
→
Authorization: Bearer ***
```

```text
postgres://admin:secret@db:5432/app
→
postgres://admin:***@db:5432/app
```

## Privacy Boundary

The bundle does **not** copy:

- Docker volume contents;
- full container filesystems;
- bind-mount files;
- database files;
- Docker Desktop VHDX contents;
- arbitrary host files.

`Mountpoint` and file paths may appear as metadata, but the user's home-directory prefix is normalized.

## ZIP Implementation

P13.07 adds no third-party ZIP library.

`simpleZip.ts` writes standards-compatible ZIP archives using the ZIP `STORE` method:

- local file headers;
- CRC32;
- central directory;
- end-of-central-directory record;
- UTF-8 filenames.

This avoids adding another native/runtime dependency to the Electron package.

## User Flow

```text
Audit & Recovery
      ↓
Export diagnostics bundle
      ↓
Windows Save Dialog
      ↓
Collect + Redact
      ↓
manifest.json
      ↓
ZIP
      ↓
Result summary
```

The Renderer does not provide an arbitrary output path to the Main process.

Electron Main owns the Save Dialog and selected destination.

## Result UI

After export the Audit page displays:

- result message;
- selected path;
- file count;
- ZIP size;
- collector failure count.

A cancelled Save Dialog returns a normal cancelled result rather than an error.

## Security Architecture

```text
React Renderer
      ↓
diagnosticsBundle.export()
      ↓
Preload
      ↓
diagnostics:export-bundle
      ↓
Electron Main
      ├── Save Dialog
      ├── DiagnosticsBundleService
      ├── mandatory redaction
      └── ZIP writer
```

No shell command or filesystem destination is accepted from Renderer.

## Important Limitation

Redaction is best-effort.

Docker/application logs can contain arbitrary user/application text, so no automated redaction system can guarantee removal of every possible secret.

The generated `README.txt`, `manifest.json`, UI, and Guide all instruct the user to review the archive before sharing it outside a trusted support channel.

## Acceptance Criteria

- [x] One ZIP diagnostics bundle can be exported from Audit & Recovery.
- [x] Main process owns the Save Dialog.
- [x] Renderer cannot choose an arbitrary filesystem destination through IPC.
- [x] Bundle contains a human-readable README.
- [x] Bundle contains a machine-readable manifest.
- [x] Docker Engine, disk, container, Compose, image, network, port, graph, volume and BuildKit data are collected.
- [x] Monitoring data is included.
- [x] Task Center data is included.
- [x] Audit and recovery metadata are included.
- [x] VHDX metadata is included when available.
- [x] Recent per-container logs/diagnostics are bounded.
- [x] Collector failures do not abort the entire export.
- [x] Sensitive-key recursive redaction is mandatory.
- [x] Secret/token/connection-string/credential-URL patterns are masked.
- [x] Home-directory paths are normalized.
- [x] Volume contents and container filesystems are not copied.
- [x] No third-party ZIP dependency is added.
- [x] Page-specific Guide documents sharing/privacy limitations.
